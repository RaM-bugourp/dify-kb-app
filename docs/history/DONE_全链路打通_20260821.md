# dify-kb-app 全链路打通（后端+前端+对外API）

## 目标
按计划推进阶段 1~4：补上 G1 文档上传断点，统一存储，接入真实云 Dify 检索，落地对外 API 层，并把前端管理界面补齐。

## 关键改动与结论

### 1. server/index.js 全量重写（17KB）
- 抽取通用 multipart 字节解析器 `parseMultipart(body, boundaryBuf)`，图片与文档上传共用，彻底绕开 multer/busboy 的中文文件名 latin1 乱码。
- 新增文档路由：POST /api/documents（上传+后台解析）、GET /:id、GET /:id/download、DELETE /:id、POST /:id/sync-dify。
- 新增术语表同步：POST /api/tables/:id/sync-dify（表→Markdown 文本序列化后推送 Dify）。
- 新增对外 API 层 `/api/v1`（Bearer 鉴权 requireAuth）：GET /health、/tree、/datasets，POST /retrieval，GET /tables/:id/rows、/documents/:id、/files/:id/download。

### 2. config.js 加载时机修复（关键 bug）
- 原 `loadEnv()` 只在 index.js 里手动调用，但 dify-bridge.js 在 import 时已读取配置 → 导致永远是 mock 模式。
- 修复：`loadEnv()` 在 config.js 模块底部立即自执行，import 即生效 → mode 正确切到 real。

### 3. 前端增强
- App.tsx：文档上传按钮、文档卡片（下载/删除/同步/解析预览）、检索测试台弹窗、Dify 模式显示。
- api.ts/types.ts：新增文档与检索相关 API，DocItem 补 parsedText/difyDocId/error 字段。

### 4. 端到端验证（全通过）
- md 上传→解析(88字符)→同步 Dify(docId 返回)→检索(score 0.785)→对外 API(records=1)。
- 鉴权：无 token 401，Bearer 通过。
- 测试数据已清理干净。

## 结论
G1 文档上传断点已闭合，存储统一到 files/，Dify 真实检索链路可用，对外 API 骨架就绪。剩余：图片 OCR/多模态选型、JSON 原子写、正式鉴权 token、npm 漏洞。
