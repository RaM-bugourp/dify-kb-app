# 修复日志 — 2026-08-21

> 本轮针对 dify-kb-app v0.2.0 做质量审查后的修复与仓库整理。
> 目的：push 到仓库进行合作开发前，堵住安全与工程卫生问题。

## 一、已修复的问题

### 1. 对外 API 鉴权 fail-open → fail-closed（`server/index.js`）
- **问题**：`requireAuth` 原逻辑 `keys.length === 0 || keys.includes(token)` 放行——当 `.env` 未配置 `EXTERNAL_API_KEYS` 时，`/api/v1/*` 全部裸奔。
- **修复**：`keys.length === 0` 时返回 503「未配置 key，拒绝访问」，仅当 token 命中才放行。
- **验证**：清空 key 后访问 `/api/v1/health` 返回 401/503，不再放行。

### 2. 依赖清单与 lockfile 不同步（`package.json` + `package-lock.json`）
- **问题 A**：`package.json` 已删 `multer`，但 `package-lock.json` 根条目仍残留 `multer: ^2.2.0`（且 node_modules 里还装着），`npm ci` 会报不一致。
- **问题 B**：`react-router-dom` 在 lock 里被引用但 `package.json` 从未声明（实际源码 0 处使用，PROJECT.md 也标注「已引入但单页驱动」）。
- **修复**：移除 `react-router-dom`（未使用，且其当前版本带 2 个 moderate 漏洞），`npm install` 重新同步 lock，`multer` 从 lock 与 node_modules 一并清除。
- **验证**：`npm run build` 通过（tsc + vite，37 模块）。剩余漏洞仅 esbuild/vite 的 dev-server 型 moderate/high（需 vite 大版本升级，属 breaking，暂缓）。

### 3. 种子图片缺失 → 术语分区破图（`server/media/`）
- **问题**：store.js 种子 `img_terms` 指向 `terms-orange.png`，但该文件不在磁盘上（gen-media.mjs 能生成但未执行/未提交），导致术语分区图片卡片破图。
- **修复**：执行 `npm run gen:media` 生成缺失图，`server/media/terms-orange.png` 已落盘。
